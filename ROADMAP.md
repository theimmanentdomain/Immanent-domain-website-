# Immanent Domain — Site Roadmap

## Current State (Phase 1: Public Static Site)

Static Next.js export. No accounts, no database, no dynamic content.

Pages live: Home, Manifesto, Magazine, Critique, Projects, Videos, Creatives, Events, Submissions, Contact.

---

## Phase 2: IMDO OS — Internal Infrastructure

The operating system for the house. Not a SaaS product. Not a public-facing platform.
Internal tooling that makes the relational and operational work faster and more legible.

### 2a. Accounts and Identity
- User accounts with institutional roles: contributor, creative, collaborator, operator
- Auth via Supabase or similar
- Profile pages (public-facing, opt-in)
- Contact registry (internal, not public)

### 2b. CRM and Contact Management
- Contact records: name, role, relationship, history
- Pipeline tracking: submission, project inquiry, event inquiry
- Not for marketing. For coordination.

### 2c. Content Management
- Admin interface for publishing magazine pieces without code deploys
- Draft/review/publish workflow
- Contributor management: bylines, bios, payment tracking

### 2d. Calendar and Scheduling
- Internal event calendar (not a public ticketing system)
- RSVP management for private and semi-public programs
- Coordination with creatives and collaborators

### 2e. Project Management
- Project records linked to creatives, events, and publications
- Status tracking: development, production, completed, archived
- Brief and document storage

### 2f. Archive
- Documentation for past events and performances
- Photo, video, and text record management
- Searchable by project, date, contributor

---

## Phase 3: Public Expansion

- Public contributor profiles (approved, opt-in)
- Public project pages with full documentation
- Video archive with embedded media
- Event listings with registration (for public programs)
- Issue archive (all back issues)

---

## Constraints (permanent)

- Black background. White serif type. No gradients, cards, rounded UI.
- No colors except black and near-white.
- No startup aesthetic. No platform aesthetic.
- theimmanentdomain@gmail.com is the institutional contact address.
- Future user accounts use personal emails, not the institutional address.
- Static export preserved until dynamic features genuinely require server rendering.
